# Feedback and project memory

A comment belongs to a particular version and timecode. Record the original wording, intended change, protected context, status and evidence. Use open → applied → verified; accepted means explicit author acceptance. A rejected version remains rejected until a new change is reviewed. Cancelled means the task was withdrawn.

Reusable preferences belong in preferences.json, with scope and rationale. Shot-specific removal, travel facts and one-off duration constraints stay in the scene/feedback. Written instructions do not fix a timeline. A good idea does not establish acceptance of the resulting edit.

Before a change, save the current version. After it, inspect the changed section and adjacent context, and compare protected tracks. Export one clearly named review version. Replay is optional; a local feedback file works. Never close external comments automatically merely because a script succeeded.

Update STATUS.md with current version, source/export identities, actual coverage, unresolved issues and next step. When handing off, confirm the destination has the project export and required media; a shared folder or saved chat alone does not prove delivery. Only one writer changes the same Resolve project at a time.
